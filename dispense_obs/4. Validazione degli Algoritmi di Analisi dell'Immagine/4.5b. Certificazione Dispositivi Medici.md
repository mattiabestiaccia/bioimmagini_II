## 4.5b.1 Certificazione del Software Medico

Un punto importante che esula dalla componente tecnica è la **certificazione del software come dispositivo medico**. Un software utilizzato in ambito clinico deve essere **a norma di legge certificato** da un ente certificatore.

### 4.5b.1.1 Requisiti per la Certificazione

I punti fondamentali nella concessione della certificazione sono:
1. **Validazione clinica** adeguata
2. **Manualistica** completa
3. **Documento di gestione del rischio** che contempli:
   - Eventuali malfunzionamenti del software
   - Conseguenze potenziali

---

## 4.5b.2 Classificazione del Software Medico

### 4.5b.2.1 Definizione di Dispositivo Medico

Il software per l'analisi di immagini mediche è a tutti gli effetti un **"dispositivo medico"** e rientra nella normativa corrente. La normativa impone al fabbricante (chi commercializza o distribuisce il software) di provvedere a una particolare **marcatura CE** specifica per i dispositivi medici, rilasciata da un **ente certificato**.

### 4.5b.2.2 Tipologie di Software

| Tipo | Descrizione | Certificazione |
|------|-------------|----------------|
| **Integrato** | Parte di un dispositivo medico (ecografo, scanner MR) | Certificato insieme al dispositivo |
| **Stand-alone** | Software indipendente | Classificato come "dispositivo medico attivo" |

Il Software Stand-alone viene classificato come "attivo" in quanto il suo funzionamento dipende da una **fonte di energia esterna**.

---

## 4.5b.3 Procedura di Certificazione

La certificazione richiede una serie di attività da parte del produttore:

### 4.5b.3.1 Determinare se il Software è un Dispositivo Medico

| Tipo di Software | È Dispositivo Medico? |
|------------------|----------------------|
| Produce **informazioni diagnostiche** | **Sì** |
| Cartella clinica (solo archiviazione) | No |
| **Visualizzazione di immagini** | **Sì** |
| Analisi e segmentazione | **Sì** |

### 4.5b.3.2 Individuare la Destinazione d'Uso

Il produttore deve specificare **quando è appropriato usare il software**, inclusi:
- **Valori limite** di qualità dell'immagine
- **Tipologie di acquisizione** supportate
- **Popolazione target** (range di patologie)

### 4.5b.3.3 Attribuire la Classe di Rischio

La classe viene assegnata in base al **danno potenziale** da malfunzionamento:

| Classe | Danno Potenziale | Esempio |
|--------|------------------|---------|
| **A** | Nessun danno possibile | Viewer semplice |
| **B** | Lesioni non gravi | Software di supporto decisionale |
| **C** | Morte o lesioni gravi | Software per pianificazione chirurgica |

### 4.5b.3.4 Progettazione e Fabbricazione

Questo punto implica:
- Adozione di **controllo interno di qualità** secondo specifiche **ISO**
- Predisposizione di un **fascicolo tecnico** che documenti la struttura del software

### 4.5b.3.5 Procedura di Valutazione di Conformità

Attivare la procedura appropriata in base alla **classe di rischio** individuata:
- Classe A: Autocertificazione
- Classe B/C: Valutazione da ente notificato

### 4.5b.3.6 Manuale di Installazione

Definire le istruzioni per l'installazione, inclusi:
- **Requisiti di sistema** (hardware, sistema operativo)
- **Competenza/qualifica** dell'installatore
- **Procedura di installazione** passo-passo

### 4.5b.3.7 Manuale d'Uso

Documentare le istruzioni per l'utilizzo:
- **Destinazione d'uso** e limitazioni
- **Guida operativa** completa
- **Troubleshooting** e FAQ
- **Avvertenze** e controindicazioni

### 4.5b.3.8 Procedure di Manutenzione

Definire le procedure per:
- **Aggiornamenti** software
- **Backup** e recovery
- **Ciclo di vita** del software
- **Dismissione** controllata

## 4.5b.4 Riferimenti Normativi

- **Regolamento UE 2017/745** (MDR - Medical Device Regulation)
- **IEC 62304** - Ciclo di vita del software per dispositivi medici
- **ISO 14971** - Gestione del rischio per dispositivi medici
- **ISO 13485** - Sistema di gestione della qualità per dispositivi medici
